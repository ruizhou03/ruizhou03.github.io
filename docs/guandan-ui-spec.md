# 掼蛋 UI 规格（v1）

状态：v1 定稿（2026-10-31）。第 9 节 D1–D4、D6 已按建议采纳；D5 牌桌底色留到并排示意图阶段再定。
日期：2026-10-31。
适用：`/toolbox/guandan/` 单机与联机牌桌的表现层。规则、AI、联机协议、卡面设计都不在本规格范围内。规则以 `guandan-rule-spec.md` 为准，卡面沿用现有四象限设计系统。

这份规格要解决的问题是：过去 180 多个提交都是在逐条反馈后挪像素，从没有一份文档写清楚「哪块区域多大、某个状态下显示哪些按钮、某个事件用什么方式提示」，结果改一处就坏另一处。本规格就是这三件事的唯一依据。以后改 UI，先改这份文档，再改代码。

本规格不以工作区里 2026-09-08 起未提交的 ui6 改动为基础，那批改动另行决定去留。

---

## 0. 设计原则

1. **位置恒定**：同一个按钮永远在同一个位置。不能用的按钮变灰，不隐藏、不让别的按钮挪过来。
2. **牌比字响**：桌上最显眼的永远是牌。「不出」这类状态标注必须比牌弱。
3. **一个事件只走一个通道**：每种事件固定用一种提示方式（见第 3 节），不同时弹 toast、横幅和弹窗。
4. **强度单调**：牌越大、事件越重要，反馈越强；同一档的事件反馈完全一致。
5. **看得清**：任何一手牌落桌后，至少停留到人眼能读完，才轮到下一家动作。
6. **不露工程信息**：玩家界面上不出现版本号、座位编号、模型下载、校验之类的字眼。
7. **单一尺寸源**：所有尺寸都从一个变量推出来，禁止在各个屏幕尺寸分支里单独改卡牌尺寸。

## 1. 布局网格

### 1.1 唯一尺寸源

JS 只计算一个值：手牌卡宽 `u`（CSS 变量 `--u`），其余全部在 CSS 里用 `calc()` 推出来。

| 量 | 定义 | 说明 |
| --- | --- | --- |
| `u` | 手牌卡宽 | 求解器算出，夹在 `[36px, 72px]`，再乘「手牌大小」偏好系数（0.85 / 1 / 1.25 / 1.5） |
| `h` | `1.44u` | 手牌卡高 |
| `p` | `0.86u` | 出牌区卡宽（打出的牌比手牌略小） |
| `ph` | `1.44p` | 出牌区卡高 |
| `step` | `0.39h` | 手牌同列纵向错开量（露出点数和右上花色） |
| `step-min` | `0.26h` | 列太高时允许压缩到的下限，低于它点数就被遮住 |

**求解规则**：在当前视口里，取能让第 1.2 / 1.3 节所有行都放下的最大 `u`。宽度按 15.5 列计算（2–A 共 13 列，加级牌列和王列，再留半列余量）。偏好系数放大后放不下，手牌区就横向滚动，其余区域不受影响（设备验收允许手牌横向滚动）。

**禁止**：在任何 `@media` 分支里直接写卡牌宽高。今后屏幕尺寸分支只允许切换 1.2 宽版和 1.3 矮版两种网格。

### 1.2 宽版网格（横屏，视口高 ≥ 500 CSS px：桌面、平板）

```
┌──────────┬──────────────────────────────────────────┬──────────┐
│ 级牌条    │              对家头像 · 名字 · 张数        │  工具栏   │ r1  56px
├──────────┼──────────────────────────────────────────┼──────────┤
│          │               对家出牌区                   │          │ r2  ph + 16
├──────────┼──────────────────────────────────────────┼──────────┤
│ 上家头像  │  上家出牌区 →                  ← 下家出牌区  │ 下家头像  │ r3  1fr（最小 ph + 40）
├──────────┼──────────────────────────────────────────┼──────────┤
│ 我的头像  │   [计时] [ 不出 ] [ 提示 ] [ 出牌 ]          │          │ r4  max(56px, ph + 8)
│ 张数/托管 │   （不轮到我时：同一格显示我打出的牌）          │          │
├──────────┼──────────────────────────────────────────┼──────────┤
│          │                 手  牌                    │ 理牌 ⋯   │ r5  h + 4·step + 8
└──────────┴──────────────────────────────────────────┴──────────┘
                                                         r6  max(8px, 底部安全区)
列宽：左栏 72px ｜ 主区 1fr ｜ 右栏 72px
```

- 牌桌铺满视口，去掉页面级的「掼蛋」标题和顶部留白。
- 「决策带」r4 保留现有的同格互斥设计：轮到我时显示按钮，不轮到我时显示我打出的牌。这个设计本身是对的，因为轮到我时，我上一手牌要么已被压过，要么这一墩已经清桌，都不必再看。
- 中区 r3 吸收所有多余高度。牌桌中心留白，不放任何常驻元素。

### 1.3 矮版网格（横屏，视口高 < 500 CSS px：手机横屏、桌面 200% 缩放）

```
┌───────────┬─────────────────────────────────────┬────────────────┐
│ 级牌条     │  对家头像  对家出牌区（横排同一行）     │ 工具栏 4×44px  │ r1  ph + 8（最小 52px）
├───────────┼─────────────────────────────────────┼────────────────┤
│ 上家头像   │  上家出牌区 →            ← 下家出牌区  │ 下家头像        │ r2  1fr
├───────────┼─────────────────────────────────────┼────────────────┤
│ 我的头像   │   [计时] [ 不出 ] [ 提示 ] [ 出牌 ]    │                │ r3  52px
├───────────┼─────────────────────────────────────┼────────────────┤
│           │               手  牌                 │ 理牌 ⋯         │ r4  h + 3·step
└───────────┴─────────────────────────────────────┴────────────────┘
左右栏 max(60px, 左右安全区 + 52px)
```

- 我的头像放在决策带那一行的左栏，不和手牌重叠，也不被任何浮层压住。
- 对家头像和对家出牌并排在同一行，省出一整行。

### 1.4 竖屏

- 触屏竖屏：保留现有的「请把手机横过来」整屏提示。
- 非触屏竖屏（窄浏览器窗口）：使用矮版网格，手牌横向滚动。

### 1.5 手牌列高

- 每列默认按 `step` 错开。某列超过 5 张时，只压缩这一列的 `step`，最低压到 `step-min`。
- 压到 `step-min` 仍放不下（9–10 张同点，极少出现）时，这一列允许向上越界，进入决策带下缘的透明区域，不推动其他元素。

### 1.6 层级（z-index 只允许这 6 个值）

| 令牌 | 值 | 内容 |
| --- | --- | --- |
| `--z-table` | 0 | 桌面、头像、出牌区、手牌 |
| `--z-lift` | 10 | 选中抬起的牌、拖拽中的牌 |
| `--z-band` | 20 | 决策带、理牌菜单 |
| `--z-fx` | 30 | 中央横幅、炸弹特效（`pointer-events: none`，永不拦截点击） |
| `--z-toast` | 40 | 系统 toast |
| `--z-dialog` | 50 | 弹窗及其遮罩 |
| `--z-system` | 60 | 横屏提示、断线重连遮罩 |

除这张表以外，任何 `z-index` 值都视为缺陷。

### 1.7 工具栏

- 所有尺寸统一放右上角，从左到右依次是：设置、榜单、声音、退出。每个按钮 44×44px，间距 8px。退出永远在最右，和其他按钮之间多留 8px。
- 级牌条统一放左上角，大字显示**本局打几**，例如「打 7」，下面一行小字是「我方 7 · 对方 4」，当前坐庄的一方加点标记。悬停或长按时提示「红桃 7 是逢人配」。

## 2. 状态 → 按钮表

### 2.1 决策带的固定槽位

```
[计时] [ 左槽：否定 ] [ 中槽：辅助 ] [ 右槽：肯定（主按钮）]
```

- 键盘映射和槽位绑定：Space = 左槽，H = 中槽，Enter = 右槽。
- 三个槽位等宽，宽度至少 88px、高度 44px，在任何状态下都不移动。
- 槽位上方有一行**提示行**（高 18px，可以为空），用来放第 3 节通道 D 的文字。
- 按钮状态只有三种：「可用」「禁用（变灰，仍占位）」「空（槽位留白但占位）」。只有整条决策带切换到「显示我打出的牌」时，按钮才整体消失。

补充规则：

- **提示按钮**：连续点击会在所有可出组合之间循环。选中的牌整体抬起，提示行显示牌型名，例如「顺子」。
- **选牌实时预判**：选牌过程中，提示行实时显示「三带二」，或者「不成牌型」「压不过」（灰字，不是报错）。右槽是否可用和这个预判一致。所以「选择不成牌型」「压不过上家」这类 toast 基本可以删掉。
- **进贡和还贡在牌桌上完成**，不再弹出 `#gdTributeOverlay` 弹窗。这是游戏动作，不应该用弹窗挡住牌桌。
- **托管入口**：我的头像旁边放一个带文字的「托管」小按钮（不再是只有图标），开启后进入 S8。
- **计时显示**：所有人都用头像外圈的倒计时圆环；只有我额外在决策带最左边显示数字。剩 5 秒及以下时数字变红，每秒响一次 tick。

### 2.3 理牌

现在的 4 个按钮（还原 / 理牌 / 一键理牌 / 调整顺序）合并成「一个随情况变化的主按钮 + 一个更多菜单」：

| 当前选中 | 主按钮文字 | 作用 |
| --- | --- | --- |
| 什么都没选 | 重排 | 清除所有自定义分组，恢复默认排序（原「一键理牌」） |
| 选了若干张散牌 | 成组 | 把选中的牌摞成一组，炸弹自动放左，其他放右（原「理牌」） |
| 选中的正好是一个自定义组 | 拆组 | 解散这一组（原「还原」） |

「⋯」菜单里放：调整顺序（进入左移/右移模式）。宽版主按钮显示文字；矮版主按钮显示图标加两个字。

### 3.3 炸弹分档（强度必须单调）

强度顺序：4 炸 < 5 炸 < 同花顺 < 6 炸 < 7 炸 < 8 炸 < 9 炸 < 10 炸 < 天王炸（见 `guandan-rules.js` 中的 `bombStrengthN`）。9 炸和 10 炸只在用逢人配凑时才会出现。

| 档 | 牌 | 横幅文字 | 横幅大小 | 出牌区 | 震屏 | 闪屏 | 时长 | 音效 | 语音 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| T1 | 4 炸 | 炸弹 | 小 | 红闪一下 | — | — | 1000ms | 小爆 | 「炸弹」 |
| T2 | 5 炸 | 五炸 | 中 | 红闪一下 | 轻 200ms | — | 1100ms | 小爆 | 「五炸」 |
| T3 | 同花顺 | 同花顺 | 中，金色 | 金闪 | 轻 200ms | — | 1200ms | 中爆 + 金属声 | 「同花顺」 |
| T4 | 6 炸 | 六炸 | 大 | 红闪两下 | 中 400ms | 一次 | 1400ms | 中爆 | 「六炸」 |
| T5 | 7–8 炸 | 七炸 / 八炸 | 大 | 红闪两下 | 强 500ms | 一次 | 1500ms | 大爆 | 「七炸」「八炸」 |
| T6 | 9–10 炸 | 九炸 / 十炸 | 特大 | 红闪三下 | 强 600ms | 两次 | 1600ms | 大爆 | 「九炸」「十炸」 |
| T7 | 天王炸 | 天王炸 | 特大，金色 | 全桌金光 | 最强 700ms | 两次 | 1800ms | 专属音效 | 「天王炸」 |

- 用户系统开启「减弱动态效果」（`prefers-reduced-motion`）时：不震屏、不闪屏，横幅只淡入淡出，音效照常。
- 横幅用词统一。不再同时出现「4 张炸弹」和「6 张炸」两种写法。

## 4. 节奏、消息与音频

### 4.1 节奏表

| 项 | 现在 | 规格 |
| --- | --- | --- |
| AI 出牌思考 | 360–680ms | 700–1100ms |
| AI 不出 | 同上 | 400–600ms |
| 一手牌最短可见时间（落桌到下一家动作） | 未定义 | ≥ 600ms |
| 三家不出后清桌 | 立即 | 停 800ms 再清 |
| 炸弹或接风横幅期间 | 不暂停 | AI 等横幅时长的 70% 再动 |
| 最后一手到摊牌 | 1000ms | 1000ms |
| 摊牌到结算 | 3000ms（WIP 值） | 3000ms，可点「跳过」 |
| 我的出牌时限 | 25s | 25s（设置里可选「不限」） |
| 进贡时限 | 5s | 10s |
| 还贡时限 | 20s | 20s |

设置里新增「AI 速度：慢 / 标准 / 快」，倍率分别是 1.4、1、0.5。调试台的「快进」和「单步」保留。

### 4.2 消息系统

- 所有提示统一走 `fx.emit(事件名, 数据)`，由它查第 3 节的表决定通道、时长、音效和语音。业务代码里不再直接调用 `toast()`，也不再直接创建横幅元素。
- 现有约 60 处 `toast()` 按第 3 节重新归类：操作类进 D，规则事件进 A、B 或 C，只有系统消息留在 E，调试台的消息只在调试台里显示。

### 4.3 音频

分三条轨道，各自有开关和音量（放在设置里）。工具栏的声音按钮点开一个小面板，里面是三个开关。

| 轨道 | 内容 | 默认 |
| --- | --- | --- |
| 音效 | 洗牌、发牌、落牌（2–3 个变体随机）、不出叩桌、炸弹三档（小、中、大）+ 天王炸专属、轮到我、tick、局终、升级、胜利乐句、失败乐句 | 开，70% |
| 语音 | 牌型播报：单张（2–A、小王、大王）、对 X、三个 X、三带二、顺子、连对、钢板、同花顺；「不要」「过」；炸弹分档用语；接风、抗贡、头游、还剩 N 张 | 开，80% |
| 音乐 | 牌桌循环段（安静，2–3 分钟可无缝循环）+ 结算短乐句 | 关；首次开局时在提示行提示一次「设置里可开背景音乐」（D1） |

- 素材要真实录音或合成人声，替换现在的方波和三角波「哔」声。
  - 音效用 CC0 素材，或者自己录。
  - 语音可以用本机已有的 CosyVoice 管线合成一套。
  - 不得翻录商业 App 的语音。
- 语音播放时，音乐自动压低 6dB。同一时刻只播一条语音，新的打断旧的。
- 首次点击时解锁音频（浏览器自动播放限制）。
- 音乐文件较大：放 R2，懒加载，不进离线必备清单。音效和语音进离线清单，打包成一个精灵文件（总量控制在 1MB 以内）。

## 7. 实施约束

1. **不动的部分**：规则、AI、联机协议、存档格式、卡面视觉、调试台。
2. **按钮由一个纯函数决定**：`bandConfig(state) → { timer, left, mid, right, hint, handMode, sortMode }` 直接对应第 2.2 节的表，只在一个地方渲染。现在散落的约 65 处 `hidden =` 赋值全部收进这个函数。
3. **反馈由一张表驱动**：`fx.emit()` 由一张数据表驱动（第 3 节），新增事件只加表行。
4. **样式重写**：表现层样式按第 1 节的网格重写成新文件，不在旧样式上叠覆盖。新文件里禁止 `!important`（读屏用的隐藏类除外），`z-index` 只能用 1.6 节的令牌。
5. **门禁照旧**：现有发布门禁全部继续适用（`guandan-device-acceptance.md`）：44×44 触控目标、200% 缩放、dialog 焦点、减弱动态效果、离线、读屏。
6. **分步上线**，每一步都能单独发布：
   1. 第 6 节删除清单 + 第 5 节文案（风险最低，立刻见效）；
   2. 第 2 节决策带与理牌；
   3. 第 1 节网格与尺寸求解器；
   4. 第 3 节反馈系统、第 4.1 节节奏；
   5. 第 4.3 节音频。
